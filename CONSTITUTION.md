# Конституция проекта: QwenWithvLLM

## Архитектурные принципы
- **Модульность**: каждый компонент (client, web, bot, tools, monitoring) независим
- **OpenAI API совместимость**: все клиенты работают через стандартный OpenAI SDK
- **Конфиг-driven**: модели переключаются через env-файлы, не через код
- **Без Docker**: нативный Python venv, прямой доступ к GPU

## Приоритеты
1. Простота запуска и использования
2. Надёжность (resume download, graceful shutdown, error handling)
3. Производительность (async, кэширование, tensor parallelism)
4. Расширяемость (легко добавить новую модель через env-конфиг)

## Ограничения и политики
- **VRAM лимит**: 64 GB (2x RTX 5090) — не предлагать модели которые не влезут
- **Безопасность**: HF_TOKEN и TELEGRAM_BOT_TOKEN только через переменные окружения, никогда в коде
- **Сеть**: vLLM слушает 0.0.0.0:8000, Web UI на 0.0.0.0:7860
- **Совместимость**: Python 3.10+, Linux (Ubuntu 22.04+), CUDA 12.1+

## Code Style
- PEP 8
- Типизация: type hints в публичных методах
- Docstrings: Google style для классов и публичных методов
- Shell скрипты: `set -e`, shebang `#!/bin/bash`, переменные в кавычках

## Запрещено
- Docker и docker-compose
- Модели больше 64 GB VRAM без явного предупреждения
- Хранение секретов в коде или конфигах (только .env)
- `import *`
- Bare except
- SQL без параметризации (в кэше shelve — ОК)
